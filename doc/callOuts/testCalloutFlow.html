How the Apex Callout Test Works

The path from the test method → real callout class → mock → assertions. The real HTTP endpoint is never hit during the test.

Test class Production callout class Salesforce runtime Mock class
1

Register the mock

AnimalsCalloutsTest.testGetCallout()

The test tells Salesforce: "for the rest of this test, don't make real callouts — use this mock instead."

Test.setMock(HttpCalloutMock.class, new AnimalsHttpCalloutMock());
calls the production method inside startTest / stopTest
2

Build the request & send

AnimalsCallouts.makeGetCallout()

The real production code builds an HttpRequest, sets the method, and calls http.send() — exactly as it would in production.

HttpRequest request = new HttpRequest();
request.setEndpoint('https://.../animals');
request.setMethod('GET');          // ← method set HERE
HttpResponse response = http.send(request);
⛔ send() is intercepted — no network call
3

Salesforce intercepts the send

Salesforce test runtime

Because a mock was registered in step 1, the runtime blocks the real HTTP call and instead routes the request into the mock's respond() method. (Live callouts are not even allowed inside tests.)

respond(request)
4

Mock builds a fake response

AnimalsHttpCalloutMock.respond()

The mock reads request.getMethod() — which returns 'GET' because that's what step 2 set — and returns a hardcoded, predictable response.

switch on request.getMethod() {   // returns 'GET'
  when 'GET' {
    response.setStatusCode(200);
    response.setBody('{"animals":[...]}');
  }
  when 'POST' { ... }
}
return response;
fake HttpResponse returned back up the chain
5

Assert against the fake response

AnimalsCalloutsTest.testGetCallout()

The response received by makeGetCallout() is the mock's fake one, so the test can assert exact, stable values.

Assert.areEqual(200, response.getStatusCode());
Assert.areEqual('application/json', response.getHeader('Content-Type'));
Assert.areEqual('{"animals":[...]}', response.getBody());
Key idea: the HTTP method (GET/POST) is set on the request in step 2 and read back by the mock in step 4 — that's how one mock class serves both makeGetCallout and makePostCallout. The real endpoint is only reached when this code runs in production; during the test the mock stands in for it, giving fast, offline, deterministic results.
